主环境为项目 `.venv` 的 Python 3.11；安装目录提供 cp37 Windows x64 wheel。隔离的 `.carla-python37/runtime/python.exe` 使用官方 Python 3.7.9 embedded runtime，并直接解包本机的 `carla-0.9.15-cp37-cp37m-win_amd64.whl`。未降级主环境。`scripts/setup_carla_client.ps1` 可重现，runtime_manifest.json 保存解释器、包路径和本地wheel SHA256。

实际版本检查均为0.9.15；已安装Town01/02/03/04/05/10HD及其Opt版本。实验使用Town10HD_Opt。首次启动记录、连接JSON、重启记录和崩溃XML位于本批 `infrastructure/`。UE Shipping未生成首个指定文本日志，不能把路径存在当作日志已经生成；实际访问冲突信息来自原始CrashContext.runtime-xml。

## 真实状态链与时钟

主进程运行SB3 PPO、Hybrid A*、速度参数化和OSQP MPC。独立3.7进程只负责CARLA RPC、车辆执行器、物理tick和测量。每个控制命令对应一个0.05秒同步帧，物理子步上限0.01秒、最多10子步。H每0.5秒决策，B1每0.05秒直接输出控制，双方共用执行器。

桥接请求包含episode_id、单调request_id和expected_frame。相同请求返回缓存响应而不再次tick；同request_id不同内容、旧回合和帧错位会拒绝。请求在执行前登记，RPC可能已推进但报错时不会盲目重试。唯一tick进程持有批次锁，发现其他车辆/传感器时拒绝接管。所有错误另记基础设施故障。

CARLA实际transform、速度、加速度、前轮转角构成状态。坐标转成右手系、逆时针弧度、后轴参考点。代码没有在执行中调用set_transform或强制设速度；内部速度积分仅是油门控制器的目标值，绝不作为返回状态。自车autopilot关闭；每回合重新spawn初始化。

碰撞以CARLA传感器事件为真值；规划几何不会代替传感器制造“实车碰撞”。碰撞消息保存回合、帧、对方actor和冲量。每帧IMU heartbeat用于发现传感器/帧故障，不等待不存在的碰撞消息。终止前保留0.3秒回调排空，再核验碰撞优先级；这不是异步传感器绝不丢包的形式保证。真实撞障诊断已确认实际事件会覆盖成功。

## 标定与适配范围

800个实际控制步覆盖三个油门档、正负转向、制动停车。将轮位的米/厘米、世界/局部四种假设，与车辆移动前后几何不变性进行比较；唯一通过的解释是世界坐标厘米，转换残差约2.77e-5 m。

实测Tesla Model3轴距3.00465m、宽2.16345m，后轴相对actor原点x=-1.38635m，后轴至前端3.81146m、至尾部0.98032m。这不同于轻量训练车2.5m轴距、1.8m宽。冻结PPO迁移明确标为**低层重新标定**，不称整个系统未经适配。

归一化steer±0.25的低速响应对应约1.082 rad/单位，符号相反；大转角全范围尚未完整扫描。启动延迟随油门档约0.6–2.2s，说明单一直线油门回归不足以解释响应。实际适配采用有限速度目标反馈、油门前馈和实测制动增益约6.26m/s²/单位；H/B1执行目标限制相同。命令限制不能当作CARLA实测加速度绝不超限，停车响应有明显尖峰，原始值和舒适性指标全部保留。

## 三类实际场景

选取已安装地图的平坦四车道封闭试验区域，按实际道路外侧边界建立34×14m局部坐标，采样验证道路表面。横向边界对应道路，纵向两端是明确的任务边界。

- static：真实停放车辆形成绕障通道，观测编码其测量bbox。
- curve：真实障碍形成弯曲行驶路线并设置偏移停车目标；这是直道路面上的弯曲试验路线，尚非不同曲率的原生弯道路网。
- dynamic：真实walker按相同condition控制横穿，观察当前位置/速度，不提供未来轨迹。

三类底层诊断均已实际执行；全程参考静态绕障、弯曲路线停车及动态等待有成功案例。规则高层的静态/弯曲路线失败也保留。所有诊断明确标diagnostic，均不计PPO结果。

开发清单与30项最终清单分离，后者为三类×10个condition，保留清单hash，开发冻结前不运行最终清单。几何生成器按condition种子抽取连续参数，避免简单取模导致不同清单实际重复条件。

## 故障与资源

首次服务发生UE访问冲突后已退出；旧调用未伪装成任务成功。只有确认进程与端口均释放后才重启本批服务。回合间清理后增加一个非策略物理帧，避免未退役对象与新spawn重叠；结束后保持空世界同步、无渲染待机，避免频繁切换渲染模式。这是针对故障的工程措施，崩溃根因尚无符号栈确认。

训练计数同时记录策略控制步、初始化/回合清理步和预算超额；最后关闭桥接的清理帧不参与PPO更新，单独视为基础设施开销。6小时总截止由batch.json统一控制，提前60秒保存并停止，独立预算守卫只会关闭本批启动且当前无其他actor的服务。

参考：[CARLA 0.9.15 Python API](https://carla.readthedocs.io/en/0.9.15/python_api/)、[同步与固定步长](https://carla.readthedocs.io/en/0.9.15/adv_synchrony_timestep/)。实现结果以本批原始帧日志为准。
